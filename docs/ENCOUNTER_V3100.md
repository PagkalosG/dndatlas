# v3.10.0 — single-campaign Battle View
DM/Creator only. GET/PUT /encounter, revision-checked singleton in a lazily created atlas_encounter table. No player projection, no new bindings. The Pages deployment verifies the existing Worker SHA, adds only the new route, validates against disposable D1, then publishes and verifies the exact module before Pages. No character data is copied into the encounter except character ID/name; PC HP remains on the existing versioned character save path. Enemy/ally HP is stored separately. Reload explicitly retrieves the latest encounter; no new polling. Last ended encounter is retained until a new one replaces it; no multi-encounter history or backup inclusion yet. Export/secure party backup remains unchanged. No digital dice, no automatic condition application. DM enters final Initiative and resolves ties, identical creatures can share a total, manual order corrections are explicit. Next/Previous navigate only and skip explicit Out participants; zero HP does not imply defeat. Rules reference: https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game

## v3.10.1
End clears initiative, out flags, active turn and round, and removes temporary enemies/allies; retains selected player references. Permanent party companions will need their own identity and persistent data when introduced. DELETE uses revision checks and stores only a null tombstone with incremented revision to prevent stale writes; no sheet mutation. Older ended snapshots are normalized on read. The staging workflow now tests the verified proposed module, including when deployment has not yet finished.
