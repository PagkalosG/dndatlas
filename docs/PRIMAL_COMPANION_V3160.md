# v3.16.0 — Character companions and Beast Master Primal Companion (2024)

The active Character and Combat renderer overrides previously omitted the existing generic companions list. Both now expose it. Beast Master Ranger level 3+ automatically gets a dedicated Primal Companion card, separate from the generic DM roster. The player selects Land, Sea or Sky, a cosmetic animal appearance, name and legal damage type. Stats derive from the owning character's Ranger level, Wisdom and proficiency bonus (total character level for PB). Land/Sea HP = 5 + 5 × Ranger level, Sky HP = 4 + 4 × Ranger level; AC = 13 + Wisdom modifier; attack = Ranger spell attack (PB + Wisdom modifier); damage and escape DC vary by form. The generic sheet spell overrides are not used because they may belong to a different multiclass spellcasting class. The stat card includes the level 7, 11 and 15 subclass rules. Source: Player's Handbook (2024), Ranger: Beast Master, cross-checked against https://dnd2024.wikidot.com/ranger:beast-master (base PHB feature only).

The sole state is character.primalCompanion, storing form, name, cosmetic appearance, damage type, missing HP, status, and replacement availability. No separate party-roster import, no duplicated HP, no additional initiative turn. DM Party View and Battle View render the same state below the owning Ranger. Combat commands explain the Ranger's Bonus Action, foregone attack and default Dodge; player can propose a Beast's Strike through the existing combat inbox, attributed to the Ranger with companion name in the action label. Action economy remains manual. HP, death and revival are manually recorded; revival requires confirmation of death within one hour and touch, consumes one available spell slot and requires a separate confirmation after one minute. Confirmed Ranger death can mark the beast vanished. A completed Long Rest unlocks replacement; no automated real-time expiry or adjudication. Companion rest recovery, conditions and hit dice spending are not independently automated. No generated dice.

Existing owner/DM permissions, character revisions and explicit Save are reused; no new tables or endpoint. No new dedicated server-side rules validator for the primal metadata: the existing character JSON validation and authorization apply. Added isolated Worker integration test for ownership, shared state and stale-write protection; run it with verified Worker source before rollout. Current production main remains v3.12.0, so the PR is cumulative with v3.13–3.15; upgrade Worker first. Verify real mobile UI and staging before production. Other class-linked companions (Find Familiar, Find Steed, summon spells) are not yet special-cased.
